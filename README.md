# 内分泌病历工作台

将用户提交的入院记录整理为可核对、可编辑的首次病程记录和上级医师查房草稿，并维护后续诊疗清单与检验结果。应用在浏览器内使用本地规则和文本模板运行，无需模型、API 密钥或患者数据库。

本项目适合文书整理、教学演示和临床工作流原型。文书框架参考 2010 年《病历书写基本规范》，并非任何医院的官方模板；正式使用前应由所在机构确认格式、数据管理要求和适用范围。去标识化导出省略真实身份和签名信息，必须在机构病历系统中据实完善并由医师核签，不能直接当作完整、已签署病历。

## 使用流程

1. 粘贴入院记录，检查去标识化结果，再核对结构化字段和证据。
2. 根据实际病情确认需要讨论的问题，生成首次病程草稿。原记录未提供的内容保留为待补充，不自动写成正常或阴性。
3. 输入实际查房信息及上级意见，生成查房草稿。未输入的意见不能变成“上级医师指出”，记录仍需实际医师核对。
4. 新增带时间、单位及参考区间的检验结果，重新查看证据、鉴别方向和后续计划。
5. 入院及复评计划按整段原文成为清单项目，保留否定、条件和先后关系；可另外添加经医师确认的独立事项，并填写备注和手动勾选。清单状态用于追踪工作，不代表正式医嘱已签署或治疗已实施。
6. 导出前再次核对身份信息和医学内容。病例默认只在当前页面内存中保留，刷新或关闭可能丢失；需要继续工作时，可自行保存去标识化 JSON。

目前提供七个讨论模块：甲状腺毒症、甲状腺结节、血糖异常、原发性醛固酮增多症方向、肾上腺功能不全方向、GH／IGF-1 异常和高钙血症方向。模块提供鉴别思路与待核实项目，不进行自动确诊、剂量计算或处方开具。

## 本地运行

网站文件位于 `dist/`，无需安装前端依赖或构建框架。请通过本地 HTTP 服务访问，直接双击 HTML 文件不能可靠运行 JavaScript 模块和离线功能。

如已安装 Python 3：

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

随后打开 `http://127.0.0.1:4173`。也可使用现有的 Node.js 静态文件服务器，将根目录设为 `dist/`。

开发验证需要 Node.js 20 或更高版本：

```sh
npm run check
npm test
npm run build
```

`build` 执行发布包核验；应用本身是可直接托管的静态文件。

## 部署到 GitHub Pages

1. 将项目源码提交到 GitHub 仓库的 `main` 分支。只提交项目文件，不要上传原始参考资料、真实病例、导出文件或密钥。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 中选择 **GitHub Actions**。
3. `.github/workflows/pages.yml` 会在推送到 `main` 时先运行检查与测试，再部署 `dist/`。也可在 Actions 页面手动执行该工作流。
4. 工作流完成后，从 `github-pages` 环境或 Pages 设置页面打开实际部署地址。

工作流使用 GitHub 提供的短期身份凭证，不需要个人访问令牌。仓库可见性与网站访问范围是不同的设置；部署前应确认实际网站的访问范围。具体配置参见 [GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## 安装与离线

在支持的浏览器中，HTTPS 网站或本地 localhost 页面可通过浏览器的“安装应用”或“添加到主屏幕”入口安装为 PWA。首次成功加载并完成资源缓存后，可离线使用已缓存的页面。安装入口和离线行为受浏览器支持情况影响。

PWA 是可安装的网站，不是经签名、公证的 macOS 原生应用或 DMG 安装包。离线缓存仅保存应用静态资源，不应保存病例输入。

## 数据与医学边界

病例处理在浏览器内完成，应用不调用远程模型，不自动上传病例，不将病例写入 localStorage 或服务器数据库。自定义屏蔽词可能含原始姓名，不写入导出的病例 JSON。网站初次加载、应用更新及主动打开参考文献仍会产生普通网络请求；托管平台可能保留访问日志。

补充屏蔽词可再次应用于整个病例而不清除随访；累计最多 200 个不同词，每词最多 200 字符，超限明确报错，不会静默忽略。若改变了计划条目的文字，该条目完成状态将重置，需要核查。医师职级前后的一般叙述不会被猜测成人名；无明确姓名标签的人员姓名须加入精确屏蔽词表。

1.0.1 将原文计划改为整段核对。导入旧版拆分计划时，不沿用旧计划项目的勾选和备注，界面会提示重新核查；请保留旧工作文件以供对照。自定义事项及仍适用的其他任务状态保留。

全部临床时间采用患者就诊地的本地时间，与设备时区无关，不自动换算时区。导入文件中的 `Z` 或 `+08:00` 等时区后缀会被明确拒绝，须先根据原始记录核对并统一时间，不能只删后缀。秒及 1–3 位小数秒可输入；同一时刻的不同文本写法会归一化。采样时间必须据原报告填写，不默认等于记录时间。

入院原文、单个事实字段、单个查房或复评文本，去标识前后均最多 80,000 字符。自定义事项和备注最多 2,000 字符；检验名称、单位、采样条件各最多 500 字符。单病例最多 200 次复评，每次最多 100 条检验，最多 100 条自定义事项；超限拒绝本次操作，不截断已接受的临床文字。

自动去标识化只能辅助识别常见姓名标签、编号和联系方式，不猜测自由叙述中的所有人名或无标签编号，不能保证识别自由叙述中的全部人名、罕见标识或可重识别组合。请在输入前去除不必要的身份信息，并检查生成内容、剪贴板、打印件及下载文件。浏览器扩展、系统剪贴板、同步下载目录及同设备使用者不受本应用控制。

本工具没有经过临床有效性验证，不能代替诊断、医嘱系统或医师签名。建议与诊断均须结合完整病情、原始报告及机构流程审核；危急情况应立即开展临床评估，不能等待文书生成。
