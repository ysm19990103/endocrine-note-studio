# 自由文本隐私检查：实现与验证

日期：2026-11-03。基线为 `main` 的 `d9ff3b134a46cf1f57cf746348cb8736640c40ce`（1.0.1）。本改动不改变 `dist/engine.js`、`dist/knowledge.js` 中的去标识、临床生成、诊疗计划、检验解释或时间规则。所有验证材料均为完全虚构的中文病例，无真实患者记录、原始参考附件、个人密钥或数据库。

## 基线边界复现

| 完全虚构的输入类型 | 原 `sanitize()` 结果 | 新增核查行为 |
| --- | --- | --- |

这些结果描述已知规则边界，不构成现有系统发生数据泄露的证据。

## 实现范围

`dist/privacy.js` 使用浏览器本地规则扫描当前病例中的入院原文、全部事实字段、查房所见及意见、历次随访文字、检验名称/单位/采样条件、自定义事项和清单备注。检验数值与临床时间不被猜测为人名。隐私检查本身不改变文字。

每条提示给出字段名、行列、上下文及高亮原文。位置对应经过原有 `sanitize()` 整理后的原文或当前字段，内部偏移为 UTF-16，显示列按 Unicode 码点计算。用户可以确认保留，或填写精确屏蔽词；屏蔽仍调用原有词表机制并作用于所有字段，可能同时影响该词的临床用法，必须复核。无“全部忽略”按钮。

逐项处理后，仍须勾选原有全文隐私与事实确认项。修改、补充词表、追加随访、清单变动、重新整理、导入及新建病例均撤销相应确认；确认状态与检测片段不写入 JSON。未提交的输入不属于已核查预览。

TXT、HTML、JSON、应用复制按钮和打印按钮统一调用导出检查。原生复制/剪切只允许已确认预览内的单一选区；输入框及未整理原文的原生复制/剪切被阻断。浏览器菜单打印通过 `beforeprint` 重新核查，打印样式默认只显示阻断说明，批准后仅输出独立的病历正文节点。不能防止用户主动用开发者工具、截图、浏览器扩展或操作系统捕获已显示文字。

单次最多显示 250 条提示；额外发现时显示“至少”数量，并持续阻断导出。用户先屏蔽确认的标识或精简内容，再查看剩余提示，不会把被截在显示上限之外的内容算作通过。扫描失败时清除有效状态，后续必须重新扫描成功。

## 隐私与临床保护

- 新增检查不使用网络、模型、遥测、日志、localStorage、sessionStorage、IndexedDB 或 Cookie。页面连接策略为 `connect-src 'none'`；应用更新仍请求同源静态资源，服务工作线程只缓存固定静态资源路径。
- 提示、原文窗口和屏蔽上下文均作为文本节点渲染；HTML 导出继续转义用户文字并使用禁止脚本的 CSP。
- 姓名/联系方式/编号/叙述性身份信息规则只提示风险。常见疾病、单位、数值、否定句、条件性计划、基因和转录本编码有合成负对照。
- 屏蔽词和审查状态仅留在页面内存；JSON 导出排除词表和审查数据，重新导入需重新核查。

## 独立只读审查

独立审查者只读取代码并运行合成/故障注入测试，未修改项目文件；修正由原实现者完成，再交回复核。

| 发现 | 修正与回归 |
| --- | --- |
| 扫描异常前已写入快照，后续可能复用旧状态 | 扫描成功后原子提交报告和快照，异常时清空并撤销 `valid`；故障注入验证同快照重试 |
| `[已移除]` 搜索副本形成不存在的空格片段，可能推荐屏蔽“住在/在” | 使用原文切片，排除连接词和泛称；叙述性身份提示不默认提供整段屏蔽词 |
| 已确认病例可能放行尚未提交输入的原生复制 | 复制/剪切仅允许已确认正文的单一选区，拒绝输入控件；浏览器回归覆盖原文及待提交随访 |
| 密集匹配计算全部位置导致同步扫描卡顿 | 只收集显示上限加一条即停止并阻断导出；36 KB/72 KB 合成文本复测约数毫秒，非全设备性能保证 |
| 头衔在前、家属患病及陪送叙述漏检 | 补充常见语境并增加合成测试；仍不声称通用姓名识别 |
| 无空格检验值和单位被误报编号 | 增加常见值/单位及医学编码负对照，保持文字不变 |

最终独立源码复核未发现应阻止提交 PR 的剩余问题。审查没有使用真实病例，没有临床有效性或匿名化认证含义。

## 未建立的保证

规则可能漏掉没有明显语境的姓名、少见姓氏、外文/混写姓名、特殊号码、罕见叙事和信息组合；例如“到院前曾与阿依古丽交谈”仍须人工识别并补充屏蔽。也可能把陌生医学编码或必要背景提示为风险，由使用者决定保留。没有测量真实病例上的敏感度、特异度或重识别风险，不能保证完全匿名化。Firefox、Safari、移动浏览器、操作系统剪贴板同步和实际打印设备不在本次 Chromium 验证范围内。
